# App Proxy

Нативное приложение для macOS 15 и новее. Выберите приложения, чтобы направить их
TCP- и UDP-соединения через SOCKS5-прокси. Интерфейс использует SwiftUI.
Системное расширение использует штатный `NETransparentProxyProvider`.

## Возможности

- Выбор приложений без изменения их настроек.
- Одно правило для основного приложения и его вложенных вспомогательных процессов.
- Изменение выбора при работающем прокси. Новые правила действуют для новых соединений.
- Поддержка TCP и UDP через SOCKS5 без пароля.
- Сохранение настроек между запусками.

## Сборка

Потребуются Xcode с Swift 6.2 или новее и аккаунт Apple Developer.

1. Откройте `AppProxy.xcodeproj`.
2. Выберите свою команду в Signing & Capabilities для целей `AppProxy` и `Proxy`.
3. Укажите уникальные bundle identifiers. Обновите `ProxyConfiguration.providerID`,
   идентификатор расширения и группу приложений в entitlements, если меняете идентификаторы.
4. Соберите схему `AppProxy`.
5. Поместите `App Proxy.app` в `/Applications`.
6. При первом включении разрешите сетевое расширение и конфигурацию в macOS.

Сборка из терминала:

```sh
xcodebuild -project AppProxy.xcodeproj -scheme AppProxy -configuration Debug \
  -derivedDataPath .build -allowProvisioningUpdates DEVELOPMENT_TEAM=YOUR_TEAM_ID build
```

При первой сборке на новом Mac добавьте `-allowProvisioningDeviceRegistration`,
если Xcode должен зарегистрировать устройство в аккаунте разработчика.
Текущая конфигурация использует Apple Development. Для распространения через Developer ID
потребуются соответствующие профили, entitlements и нотарификация.

## Использование

1. Запустите SOCKS5-прокси с поддержкой UDP ASSOCIATE.
2. Откройте App Proxy и укажите адрес и порт. По умолчанию: `127.0.0.1:10888`.
3. Выберите приложения и нажмите «Включить».
4. Создайте новые соединения в выбранных приложениях.

Для локального sing-box можно использовать вход типа `mixed`: он принимает HTTP
и SOCKS5 на одном порту. App Proxy не меняет конфигурацию вашего прокси-сервера.

## Ограничения

- macOS может отправлять системные DNS-запросы обычным подключением.
- Системные службы могут создавать соединения от своего имени. Правило приложения не охватывает их автоматически.
- Расширение обрабатывает TCP и UDP, но не произвольные IP-протоколы.
- Реализация не поддерживает аутентификацию SOCKS5 и фрагментацию UDP в SOCKS5.
- Отказ прокси может завершить соединение с ошибкой. App Proxy не повторяет его напрямую и не реализует отдельный kill switch.
- Изменение выбора не переносит уже открытые соединения на другой маршрут.

## Проверка

```sh
brew install sing-box
python3 Tests/run.py
git diff --check
```

Тест запускает отдельный sing-box на временном локальном порту. Он проверяет
протокол SOCKS5, передачу TCP после завершения отправки, UDP, ошибки подключения
и определение основного приложения по пути вложенного процесса.

Ручная проверка подтвердила загрузку сайта в Safari через расширение и подключение MAX
к API с отображением QR-кода для входа. Проверка не включала сообщения, звонки
и полный перехват DNS. Проверка интерфейса подтвердила изменение выбора без остановки прокси.
